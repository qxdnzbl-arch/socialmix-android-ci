# 双机传执行与验收

源码及验收设施的小改先批量完成快速检查。完整原生 UI/内置更新验收由 `.github/workflows/dual-phone-ui-update.yml` 执行，只在最终候选准备好时更新 `dualphone/ci/run-ui-update.txt`，或在 `dual-phone-transfer-build` 分支发起一次 workflow_dispatch。已授权任务的验收继续自动完成，不再向用户重复申请许可。不要在讨论、改机制或逐文件施工时触发完整模拟器及发布。

启动昂贵操作前先读项目状态和已通过的证据，使用已安装的 execute-results 技能行动前检查。依赖未变的已验收段优先保留；测试设施/发布/下载失败只修相关段。复用必须保存原运行来源、范围、完整输入依赖和证据哈希；源码、相关测试、环境或版本变化时重验受影响段。缺少完整依赖清单时先核实，不把 app 目录相同说成整个验收环境相同。

同一状态两次无新进展后读取直接日志或检查可行备用路径。不要盲等、整链重做、擅自开收费资源或让用户重新下载已交付的同一版本。产品代码修改仍需适当真实 Android 验收；性能、升级保留数据与签名校验不可省略。

已经交付并通过验收的 APK、版本号和在线更新通道，不因机制维护而改动或重新发布。
